# Storage Module

This module provides persistent storage and facilitates the creation of hierarchical data structures.<br />
Documents may have complex structures and subcollections and can be stored locally or on a cloud provider.

## Features ✔️

- Local storage
- Microsoft Azure
- Google Cloud
- AWS S3 (or any other S3-compatible provider)
- Alibaba Cloud (Aliyun)

## Signed downloads

Every signed read sets `Content-Disposition` from the file `alias`, then the object name. `download=true` sends `attachment`. Otherwise the disposition is `inline`.

S3, Google Cloud, Aliyun, and local storage also send the RFC 5987 `filename*` parameter. Azure shared access signatures reject that parameter in `rscd`. When the display name is printable ASCII after control characters, quotes, and backslashes are removed, Azure receives `filename="..."`. When any character falls outside printable ASCII, or nothing remains, Conduit omits `Content-Disposition` and the browser uses the blob name.

Private files do not store `url` or `sourceUrl`. Clients resolve a private file through `GET /storage/getFileUrl/:id`.

## Environment Variables 📃 <a name="env-vars"></a>

|       Variable       | Description                                          | Required |      Example       |
|:--------------------:|:-----------------------------------------------------| :------: |:------------------:|
|   `CONDUIT_SERVER`   | Conduit Core's address and port                      |   True   |  `0.0.0.0:55152`   |
|     `SERVICE_URL`    | This should be where this service listens on. If behind a LB it should point to the LB's IP/DNS  |   False   |  `0.0.0.0:55190`   |
|     `GRPC_PORT`      | The port number the gRPC server will listen to                      |  False   |  `55190`           |
|     `GRPC_KEY`       | Specifying a secret enables gRPC signed request protection (**use across modules**) |   False  | `someRandomSecret` |
